# Release setup (local build, no EAS cloud)

`fastlane/README.md` is auto-generated by fastlane on every run — keep the real
notes here.

Builds 비타망고 on the Mac (free) and uploads to the stores with release notes
from [`../release-notes.json`](../release-notes.json).

The repository also includes a checksum-verified, repo-local App Store Connect
CLI setup:

- `yarn asc:install` → install the pinned `asc` binary into `app/bin/`
- `yarn asc -- apps list --output table` → run `asc` with credentials from
  `app/.env` without writing them to the system keychain

- `bundle exec fastlane ios beta` → build .ipa → **TestFlight**
- `bundle exec fastlane android beta` → build .aab → **Play internal** (skip if not using Play)
- Create the initial App Store Connect app record once in the web UI. Apple does
  not expose app creation to API-key clients.
- Repository root: `yarn build:ios-prod` → build locally, upload, and request
  App Review with manual release after that initial app record exists.
- Repository root: `yarn build:android-prod` → build locally and upload to the
  Play production track.

Each lane bumps the build number in `app.json`, runs `expo prebuild`, `pod
install` (iOS), builds locally, and uploads the binary + the localized changelog
for the current version (falls back to the generic `default` note).

## Prerequisites

- **Xcode** + command line tools (`xcode-select --install`)
- **Modern Ruby** (system Ruby 2.6 breaks native gems): `brew install ruby` and
  put `/opt/homebrew/opt/ruby/bin` on PATH.
- **CocoaPods** via brew (avoids the system-ruby ffi breakage):
  `brew install cocoapods` — verify `which pod` → `/opt/homebrew/bin/pod`.
- **fastlane**: `cd app && bundle config set --local path vendor/bundle && bundle install`

## App Store Connect API key (iOS)

App Store Connect → Users and Access → Integrations → App Store Connect API →
generate a key (role: App Manager) → download the `.p8` (**one-time download**).
Keep it in `app/secrets/` (gitignored). Then:

```bash
export ASC_KEY_ID="XXXXXXXXXX"
export ASC_ISSUER_ID="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
export ASC_KEY_PATH="$PWD/secrets/AuthKey_XXXXXXXXXX.p8"
```

The 비타망고 app record already exists (Apple ID `6802001217`). `app/.env` carries
it as `ASC_APP_ID`, which `scripts/publish-ios-asc.sh` reads so it can skip the
bundle-id lookup. If `asc apps list` does not show the app, the API key does not
have access to it — check the key's role/app scope in App Store Connect.

## Play service account (Android — only if publishing to Play)

Play Console → API access → service account with a `.json` key + release
permission. Then `export PLAY_JSON_KEY_PATH="$PWD/secrets/play-service-account.json"`.

## Run

```bash
# From the repository root. This is the production one-command path.
yarn build:ios-prod

# Restricted-host fallback: keep the existing native binary, embed the current
# Expo bundle, and re-sign without importing the distribution key into Keychain.
yarn build:ios-keychainless

# Direct App Store Connect CLI access (from the repository root)
yarn asc -- auth status
yarn asc -- apps list --output table

# Validate the prepared version, upload its IPA, and request App Review.
yarn asc:publish

# TestFlight only, without App Review submission.
cd app && bundle exec fastlane ios beta
```

The production command verifies that the App Store Connect app record exists,
increments only the iOS build number, regenerates the native project,
creates/fetches signing assets, builds the IPA, uploads it, waits for processing,
and requests App Review. The release remains manual after Apple approves it.

App Review still requires the app's store listing, screenshots, privacy details,
age rating, pricing/availability, and review contact information to be complete
in App Store Connect. Fastlane uploads the binary and requests review; Apple will
reject the request with a precise missing-field error until those one-time
listing fields are complete.

## Editing release notes

Edit [`../release-notes.json`](../release-notes.json). Add a block keyed by the
`app.json` version for version-specific notes, or rely on `default` (the generic
"안정성 개선 및 버그 수정" note) for routine updates.
